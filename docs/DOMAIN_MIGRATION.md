# Переезд «Архива КВМ» на kvmarchive.ru

> Статус: домен `kvmarchive.ru` куплен владельцем. **Не переключать рабочий сайт и поисковые адреса до настройки GitHub Pages, DNS и HTTPS.** Текущий адрес: https://dva5ru.github.io/kvm-guide/

## 1. Домен и безопасность

- Домен `kvmarchive.ru` куплен владельцем. Уточнить регистратора и обеспечить доступ к управлению DNS.
- Зарегистрировать домен на владельца проекта, подтвердить контактные данные, включить автопродление и двухфакторную защиту учётной записи.
- Для .ru у некоторых регистраторов требуется подтверждение администратора через ЕСИА. Не покупать отдельный хостинг, платный SSL или почтовый сервер ради GitHub Pages.
- В настройках GitHub профиля (`dva5ru` → Settings → Pages) по возможности сначала **верифицировать домен** с TXT-записью по инструкции GitHub; оставить TXT после проверки.

## 2. GitHub Pages и DNS (после подтверждения владения)

- В репозитории `dva5ru/kvm-guide` открыть **Settings → Pages → Custom domain**, указать зарегистрированное имя без `https://` и сохранить. Если Pages публикуется из ветки, GitHub создаст корневой `CNAME`; если из Actions — домен задаётся в Pages, файл может не использоваться.
- Для `kvmarchive.ru` внести в DNS регистратора четыре записи `A` с именем `@`:
  - `185.199.108.153`
  - `185.199.109.153`
  - `185.199.110.153`
  - `185.199.111.153`
- `www`: запись `CNAME` имени `www` → `dva5ru.github.io` (не `dva5ru.github.io/kvm-guide` и не `kvmarchive.ru`). Убедиться, что нет конфликтующих `A`, `AAAA`, `CNAME` записей.
- Проверить `A`/`CNAME`, работу как с `www`, так и без; выбрать единственный главный домен. После выпуска сертификата в Pages поставить галку **Enforce HTTPS**. Пропагация DNS и выпуск сертификата могут быть не мгновенными.
- Не использовать wildcard `*.kvmarchive.ru`; не перенастраивать `NS` на хостинг без необходимости.

## 3. Код и контент при фактическом переключении

- Обновить в `index.html` абсолютные `og:url` и `og:image` (сейчас старый Pages URL), добавить canonical для нового главного URL.
- Обновить метаданные `articles.html`, `article-*.html`, `legal.html`, сделать реальные превью карточек статей для мессенджеров. Соцсети не обязаны выполнять JS, поэтому метатеги должны быть в HTML при отдаче страницы.
- Обновить публичную ссылку в README и документации, проверить другие внешние ссылки и ссылки в статьях. Динамические и относительные пути к `assets/`, `data/`, `img/`, `content.json` должны продолжать работать при переносе из `/kvm-guide/` в `/`.
- Запустить `npm run stamp`, `npm run validate`, `npm test`; проверить GitHub Actions и фактический деплой.
- `sw.js` кеширует картинки в пределах origin и scope: при смене домена посетители получат отдельный кеш, это ожидаемо. Проверить первое открытие и повторную загрузку, отсутствие 404 на `/img/`, `/assets/`, `/data/`.
- Админка сохраняет токен GitHub в `localStorage` **отдельно для каждого домена**: после переезда авторизоваться заново (репозиторий `dva5ru/kvm-guide`, ветка `main`). Никогда не переносить токен в исходники. На кастомном домене форма теперь подставляет правильный репозиторий.

## 4. SEO и переходы

- После запуска создать/обновить `sitemap.xml` с **новым** доменом и `robots.txt` со ссылкой на него; не публиковать sitemap с непринадлежащим доменом заранее.
- Добавить и подтвердить `https://kvmarchive.ru` в Google Search Console и Яндекс Вебмастер; отправить sitemap и проверить индексацию.
- Протестировать старые ссылки `https://dva5ru.github.io/kvm-guide/`, `.../articles.html`, `.../article-vision.html` и их аналоги с `#`; проверить, что пользователь попадает в соответствующий новый раздел, а не на 404. Не предполагать автоматически, что все редиректы совпадут.
- Для смены адреса Google/Яндекс рекомендуют постоянные серверные редиректы. GitHub Pages не предоставляет произвольных правил 301, поэтому проверить доступный редирект старого Pages-адреса отдельно; инструмент Change of Address Google требует владения и старым, и новым ресурсом, что для `github.io` может быть невозможно.
- **Текущая архитектура hash-роутинга (`#heroes`, `#f-...`) не даёт отдельного индексируемого URL каждому персонажу.** Человекочитаемые пути и отдельные SEO-страницы — следующий этап, не блокер смены домена.

## 5. Финальная приёмка

- Новый домен открывается по HTTPS с валидным сертификатом, `www` ведёт на основной адрес.
- Проверены главная, статьи, каталог, хронология, карты, поиск, режим PRO и мобильный интерфейс.
- Проверена авторизация в редакторе и публикация тестовой безопасной правки.
- Telegram-превью показывает корректную картинку, заголовок и ссылку нового домена.
- Заявлены sitemap и поисковые ресурсы, основные старые ссылки протестированы.
