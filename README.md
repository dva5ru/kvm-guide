# Архив КВМ

Фанатская энциклопедия киновселенной Marvel: хронология, каталог фильмов и сериалов, герои, энциклопедия, карты и порядок просмотра.

Сайт: https://kvmarchive.ru/

## Что где лежит

```
index.html            главная страница: только разметка и список файлов данных (блок kvm-data-files)
articles.html         страница «Разбираемся в КВМ» (статьи)
legal.html            страница «Источники и права»
content.json          правки из редактора сайта: тексты, картинки, скрытые блоки, места точек на картах
img/                  картинки, загруженные через редактор
sw.js                 кеш картинок для повторных визитов

assets/
  css/                стили: app.css (весь сайт), map-atlas.css (атлас карт), story-layout.css (сюжеты),
                      home-v6.css (главная), pro-mode.css (режим PRO), articles.css (статьи)
  js/                 скрипты: data-loader.js (загрузчик данных), app.js (весь код сайта и редактора), home-v6.js (главная),
                      spoiler-index.js (разметка спойлеров, сейчас отключена)
  maps/nyc.json       карта Нью-Йорка (границы районов, NYC Open Data)

  characters.json       герои
  appearances.json      появления героев в проектах: кто, где и в какой роли (грузится сразу)
  appearance-details.json  описания ролей, роли по сериям и источники (грузится на страницах героя, проекта и серии)
  episodes.json         серии: номера, названия, даты (грузится сразу)

  catalog.json          сюжетные линии, маршруты, эпохи, студии, статусы
  versions.json         версии и издания
  search.json           поисковые синонимы и английские названия
  maps.json             карты, космос и древо миров (грузится на карте и страницах мест)

  EDITORIAL_SITEWIDE.md   даты, появления, переиздания и анонсы

  SPOILER_PROTECTION.md   защита от спойлеров

  reports/            отчёты
  data/               данные проверок, их читают тесты

scripts/
  validate-guide.mjs  проверка базы данных сайта
  stamp-assets.mjs    проставляет версии файлов из assets/ и data/ и выравнивает формат data/ (npm run stamp)

  migrations/         разовые скрипты переноса (история)

  lib/                общие функции для проверок; guide-source.mjs собирает сайт из файлов для тестов
```

## Что нельзя переносить и переименовывать

- `index.html`, `articles.html`, `legal.html` — GitHub Pages открывает страницы по этим адресам.
- `content.json` и `img/` — сюда пишет редактор сайта. Руками их не правим.
- `sw.js` — кеш работает только из корня сайта.

## Как править содержание

Тексты, картинки, скрытые блоки и места точек на картах правятся прямо на сайте:

1. Откройте сайт с `#admin` в конце адреса и войдите (нужен токен GitHub).
2. Нажмите «✎ Править» и внесите изменения.
3. Нажмите «Опубликовать» — правки сохранятся в `content.json`, картинки — в `img/`.

Менять для этого `index.html` не нужно.

## Как менять код и данные

- **Данные сайта** (проекты, герои, места, события, серии) лежат в папке `data/`. Загрузчик `assets/js/data-loader.js` сразу загружает основные файлы, собирает одну общую базу и запускает код сайта. Подробности, карты и глобус догружаются в ту же базу, только когда их открывают (список — в блоке `kvm-data-files` в `index.html`, поле `lazy`). Поиск работает на основных файлах и всегда полный.
- Правки из редактора (`content.json`) всегда накладываются поверх данных, в том числе после каждой догрузки. В редакторе (`#admin`) все данные загружаются сразу.
- Описание роли героя в проекте правится в `appearance-details.json`, сюжет серии — в `episode-details.json`. Новое появление или новая серия добавляются в `appearances.json` или `episodes.json`, а их тексты — в соответствующий файл подробностей с тем же `id`.
- Идентификаторы записей (`id`) не меняем: на них держатся ссылки, адреса страниц и правки редактора.
- **Код сайта и редактора** — в `assets/js/app.js`, общие стили — в `assets/css/app.css`.
- Новый файл стилей или скриптов кладите в `assets/css` или `assets/js` и подключайте в `index.html`.
- **После любой правки файлов в `assets/` или `data/` выполните `npm run stamp`.** Команда обновит версии файлов в адресах (`?v=…`), чтобы посетители сразу получили новую версию, а не старую из кеша, и выровняет формат файлов в `data/`. Если забыть, проверка на GitHub не пропустит пул-реквест.
- Новый отчёт кладите в `audit/reports` с датой в названии, данные для тестов — в `audit/data`, правила — в `docs`.

## Проверки

```
npm ci --ignore-scripts
npm run stamp
npm run validate
npm test
```

Те же проверки GitHub запускает для каждого пул-реквеста.

## Как работаем вдвоём (Claude и ChatGPT)

1. Перед работой берём свежий `main`.
2. Делаем ветку с понятным названием: `feature/…`, `fix/…`, `edit/…` или `chore/…`, с датой в конце.
3. Меняем только то, что нужно для задачи, и прогоняем проверки.
4. Открываем пул-реквест.
5. Сливаем в `main` только по команде владельца. Перед слиянием сверяемся со свежим `main`.
6. После слияния удаляем ветку.
