# Автоназначение фотографий по именам файлов

База проверки: `3725db6a7e02f00fe92faa8239ab02da23539571`.

## Воспроизведение

В исходном загрузчике 166 из 479 полных названий карточек персонажей не возвращали правильный однозначный адрес. Например, не назначались `Тони Старк / Железный человек.webp`, `Боб _ Часовой _ Пустота [bob].webp`, `Грут (первый).webp` и `1. Мак Гарган _ Скорпион [scorpion].webp`.

Причины:

- В индексе отсутствовало полное имя персонажа: учитывались только первые две части, разделённые ` / `.
- Из первой части имени удалялись уточнения в скобках. Разные версии Пегги, Грута и других героев становились одинаковыми псевдонимами.
- Полные названия и сокращённые псевдонимы имели одинаковый приоритет.
- `/` и ряд Unicode-символов нормализовались иначе, чем `_`, дефисы и пробелы.
- ID в имени загружаемого файла (`[scorpion]`, `[c-scorpion]`) не разбирался. Прежняя обработка `[c-id]` была доступна только в поле ручного назначения.
- Файлы с пустым MIME-типом или `application/octet-stream` отбрасывались до сопоставления имён, даже при корректном расширении изображения.

## Изменения

Полное имя индексируется вместе со всеми частями после `/`, сохранёнными уточнениями версии и существующим английским именем. Внутри одного типа карточек точное полное имя имеет приоритет над сокращёнными псевдонимами. Совпадения между типами (герой/фильм, герой/место) остаются неоднозначными.

Загрузчик распознаёт существующие ID с префиксом и без префикса в квадратных скобках, а также отдельное имя файла `c-scorpion.webp`. ID с префиксом определяет точную карточку; короткий ID используется только при однозначности. Неизвестный явный ID не заменяется приблизительным совпадением с другой карточкой.

Нормализация поддерживает NFKC, составные Unicode-символы, неразрывные пробелы, невидимые знаки форматирования, эквивалентные разделители, номера списка и суффикс размера `512×512`. Сохраняются значимые уточнения версии, включая год и вселенную.

Изображения с неизвестным MIME-типом принимаются при известном расширении JPEG/PNG/WEBP/GIF/AVIF/BMP. Декодирование и обработка ошибок используют существующий загрузчик.

Для файлов, оставшихся без назначения, интерфейс показывает причину и возможные карточки с ID. Если имя из прежней очереди теперь распознано, нужная карточка уже подставлена в поле: достаточно нажать «Поставить». Сделанный пользователем выбор сохраняется.

## Проверка

- 475 из 479 полных названий автоматически назначаются своей карточке. Оставшиеся четыре: `Тор` (герой и фильм), `Эго` (герой и место), две карточки `Джин Грей`. Для них сохраняется выбор пользователя.
- Все 479 названий с явным `[c-ID]` назначаются точно. Полные названия фильмов, мест и предметов также проверены на отсутствие назначения чужой карточке.
- Проверены уточнения альтернативных версий, третье имя Боба, нумерация, ID без префикса, NFD/NFKC, размеры, копия файла с `(1)`, пустой MIME-тип, пакетная загрузка и прежняя очередь.
- Проверки включены в существующий `photos.test.mjs`, который запускается в CI. Полный прогон: 74 теста; `npm run validate`; `git diff --check`.

Встроенная база персонажей, `content.json`, уже загруженные файлы и назначения изображений не изменялись. Публикация выполняется через отдельную ветку и PR с сохранением параллельных загрузок пользователя.
